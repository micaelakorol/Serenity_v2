# Serenity — Seller readiness checklist

Use this checklist before listing, transferring or delivering the template.

## Code and quality checks

- [ ] Run `npm ci` from a clean folder.
- [ ] Run `npm run lint` and resolve all reported errors.
- [ ] Run `npm test` and confirm all tests pass.
- [ ] Run `npm run build` and confirm a production build is generated.
- [ ] Run `npm run preview` and inspect the production build.
- [ ] Test keyboard navigation, skip link, mobile menu and FAQ controls.
- [ ] Test at narrow mobile, tablet, laptop and wide desktop sizes.
- [ ] Check browser console and network requests for errors.
- [ ] Check all booking, WhatsApp, email and social links.
- [ ] Run `npm audit` and review/fix applicable vulnerabilities before delivery.

## Content and customization

- [ ] Replace the sample professional identity, biography, qualifications and service descriptions.
- [ ] Confirm all claims about credentials and services are accurate.
- [ ] Update SEO title, description, canonical URL and social preview image.
- [ ] Configure a real booking URL or disable booking buttons.
- [ ] Add a real WhatsApp number or leave the field blank.
- [ ] Add a valid email address and real social profile URLs, or leave unused fields blank.
- [ ] Check image alt text and replace sample images where necessary.

## Rights and licensing

- [ ] Verify the right to redistribute all source code and third-party dependencies.
- [ ] Verify commercial-use and redistribution rights for every included image.
- [ ] Verify font, icon, illustration and other third-party asset licenses.
- [ ] Include license notices and attribution where required.
- [ ] Remove any asset whose license does not permit redistribution.

## Listing accuracy

- [ ] Describe Serenity as a website template / digital asset, not an operating business.
- [ ] Do not claim revenue, traffic, customers, bookings or business performance unless documented and accurately disclosed.
- [ ] Include the live demo URL and current screenshots.
- [ ] State exactly what the buyer receives (source code, eligible assets and documentation).
- [ ] Explain that external booking, hosting and other services may require the buyer's own accounts.
- [ ] Confirm the marketplace's current listing category, eligibility rules and fees before paying.

## Transfer package

- [ ] Remove `node_modules/`, `dist/`, local environment files and deployment credentials.
- [ ] Include the source project, `README.md`, `SELLER_CHECKLIST.md` and license notices.
- [ ] Include only assets cleared for transfer.
- [ ] Create a clean ZIP and verify that it extracts and installs successfully.
